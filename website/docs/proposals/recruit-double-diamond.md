# Recruitページ改訂案：フラクタルダイヤモンドフレームワーク

ステータス: 実装済み。2026-08-07時点。

## 中心となる考え方

> フラクタルダイヤモンドフレームワーク

> 「ダブルダイヤモンド」とは、課題の探索と解決策の検討において、発散と収束を二度繰り返す課題解決のフレームワークです。

要は、マクロな視点でもミクロな視点でも、このダブルダイヤモンドを意識して進める必要があるということです。

## AccelHackの4工程

| 工程     | Double Diamond | 動き                                     |
| -------- | -------------- | ---------------------------------------- |
| 見つける | Discover       | 可能性を広げ、課題を発見する             |
| 深ぼる   | Define         | 情報を整理し、扱う課題を定める           |
| 解を出す | Develop        | 複数の解決方法を考え、試す               |
| 実装する | Deliver        | 解決方法を絞り、利用できる状態まで届ける |

## Recruitページでの構成

1. **AccelHackの課題解決フレームワーク**<br>
   メッセージを上段、プロジェクト全体のダブルダイヤモンドを下段の全幅で表示する。外側の4工程それぞれに小さなダブルダイヤモンドを直接埋め込み、マクロなプロセスと工程内の発散・収束を一つの図で示す。そのままプロジェクト、工程、個別タスクの3つの粒度へ展開する。左右2分割の標準レイアウトは使用しない。
2. **課題解決人材への成長**<br>
   個別の実装から工程全体、プロジェクト全体へ担当範囲を広げる成長と接続する。
3. **会社・募集情報**<br>
   What's AccelHack、募集ポジション、働く環境、FAQを続ける。
4. **成長実例**<br>
   「実装する」だけを担当していたEngineerが、このフレームワークをもとに担当領域を広げ、上流エンジニアとして成功し、年収を200万円上げた実例を最後に配置する。

## 図の表現

- 外側にプロジェクト全体のダブルダイヤモンドを置く。
- 「見つける・深ぼる・解を出す・実装する」の各工程内に、小さなダブルダイヤモンドを常時表示する。
- 工程を切り替える操作は設けず、マクロとミクロの入れ子関係を一枚で読めるようにする。

## 表現上の注意

- ダブルダイヤモンドを一度だけ通過する直線的な工程として描かない。
- 「解を出す」を、一つの正解を即断する工程として描かない。
- 「実装する」を、コーディングだけに限定しない。
- 入れ子は手続きを増やすためではなく、どの粒度でも発散と収束を意識するための考え方として説明する。

## 成長実例の掲載確認

- 年収が200万円上がった事実と比較時点を確認する。
- フレームワークとの因果関係を本人へ確認する。
- 本人の掲載同意と、匿名・実名のどちらで掲載するかを確認する。
- 実際の役割変化や期間は、確認できるまで追加しない。
